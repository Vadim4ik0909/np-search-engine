## 🎯 Бізнес-контекст: Проблема vs Рішення

Сучасні контакт-центри інтернет-магазинів, товарного бізнесу та логістичні оператори в CRM-системах (**LP-CRM**, **KeyCRM**, **1C / BAS**, **SalesDrive**) щодня обробляють тисячі замовлень. Класичний процес введення поштової адреси є одним із найвужчих місць у воронці обробки лідів.

### Реальні болі операторів та e-commerce бізнесу:

1. **Колізії сіл-тезок (Географічна неоднозначність):**
   * В Україні налічується **понад 30 сіл «Андріївка»**, десятки «Василівок», 9 різних «Городків» та безліч однойменних пунктів у сусідніх районах чи областях.
   * *Наслідок:* помилка оператора веде до відправки посилки в іншу область, зриву термінів доставки, оплати подвійної переадресації коштом відправника (від 150 до 400+ грн за одне замовлення) та втрати клієнта.
2. **Габаритний колапс (Вантажні vs Поштові відділення):**
   * Клієнт замовляє великогабаритний товар (меблі, шини, генератор, промислове обладнання). Якщо оператор оформлює замовлення на звичайне поштове відділення (з обмеженням до 30 кг) замість вантажного хабу (до 1100 кг), вантаж повертається або зависає на сортувальному терміналі.
3. **Хронічна втрата часу на рутинні селекти:**
   * У класичних формах CRM оператор змушений послідовно обирати: `[Область] ➔ [Район] ➔ [Місто] ➔ [Тип відділення] ➔ [Номер]`. Це забирає **20–30 секунд на один дзвінок**, розсіює увагу та сповільнює роботу кол-центру в пікові години (до 30% робочого часу оператора).

### Рішення рушія:

> **Єдиний інтелектуальний рядок пошуку (Google / Delengine style):**
> Оператор вводить запит будь-якою мовою, у будь-якому порядку слів, із розривами чи одруками (наприклад, `городок 1 рівненська штейн`, `київ 222` чи `33830`), і за **< 2 мілісекунди** отримує точний, дезамбігуйований результат з готовими кнопками копіювання стандартизованого рядка для CRM.

## ⚡ Ключовий функціонал (Core Capabilities)

### 1. Мультифасетне звуження контексту (Progressive Narrowing)
Рушій не вимагає суворого синтаксису чи послідовного вибору. Кожне введене слово сегментується та розподіляється по сутностях:

$$\text{Запит: } \mathbf{\text{“городок 1 рівненська штейн”}}$$

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────────┐     ┌───────────────────┐
│ Топонім:        │ ──► │ Область / Район: │ ──► │ Вулиця / Орієнтир:  │ ──► │ Номер відділення: │
│ «Городок»       │     │ «Рівненська»     │     │ «Штейнгеля»         │     │ «№1»              │
└─────────────────┘     └──────────────────┘     └─────────────────────┘     └───────────────────┘
```

* **Результат:** миттєва фільтрація бази від 9 однойменних міст і сіл до єдиного цільового об'єкта: **с. Городок (Рівненський р-н), Вантажне відділення №1 (вул. барона Штейнгеля, 2-А)**.

---

### 2. Точність класифікації та системна типізація (v1.3.1)
Рушій використовує строгий валідатор категорій на основі реальних параметрів та вагових лімітів Нової пошти та Укрпошти:

* **Вантажні відділення (Cargo Hubs):**
  * Відображаються виключно об'єкти з фактичним ваговим лімітом **$\ge$ 1000 кг** або службовою категорією `Cargo`.
  * Чітка індикація максимальних габаритів вантажу: **$600 \times 220 \times 220\text{ см}$** та вантажність до 1100 кг.
* **Поштові відділення:**
  * Чітка сегментація за ваговими лімітами: **до 5 кг**, **до 10 кг** та **до 30 кг** (запобігає надсиланню великих посилок на мікропункти).
* **Поштомати:**
  * Глобальне розпізнавання **4–6 значних номерів поштоматів** по всій Україні без потреби вказувати місто (наприклад, `33159`, `поштомат 40616`).
* **Укрпошта:**
  * Прямий 5-значний індексний пошук (наприклад, `79049` $\to$ Львів, просп. Червоної Калини, 113) та повний класифікатор адресних відділень.

---

### 3. Дворівневий UX автокомпліту (в стилі LP-CRM)

* **City Mode (Вибір локації):**
  * При наборі назви населеного пункту випадаючий список виводить чіткі гео-дужки для запобігання колізіям: `Підгайці (Тернопільський р-н, Тернопільська обл.)` vs `Підгайці (Луцький р-н, Волинська обл.)`.
* **Branch Mode (Швидкий вибір відділення):**
  * Після введення номера чи вибору міста інтерфейс миттєво перемикається у режим відділень без перекриття карток результатів та без блокування подальшого набору тексту.

---

### 4. Подвійна система копіювання (Dual-Mode Clipboard)

Розроблено спеціально під робочий процес оператора для одночасного спілкування з клієнтом та внесення даних у CRM:

| Кнопка | Призначення | Формат виводу | Приклад |
| :--- | :--- | :--- | :--- |
| **«📋 Скопіювати»** | Для клієнта в чат (Telegram / Viber / SMS) | Короткий, людинозрозумілий | `місто Ужгород, Відділення №2: просп. Свободи, 63` |
| **«📋 Детально»** | Для CRM (LP-CRM, KeyCRM, 1C) | Повний з дезамбігуацією, районом та вагою | `с. Городок (Рівненський р-н, Рівненська обл.), Вантажне відділення №1 (до 1100 кг): вул. барона Штейнгеля, 2-А` |

> [!TIP]
> **Iframe Clipboard Fallback:** Рушій має автоматичний механізм обходу обмежень `navigator.clipboard.writeText()` всередині пісочниць `iframe` CRM-систем через динамічний textarea fallback (`document.execCommand('copy')`). Копіювання працює надійно в будь-якому оточенні!

## 🏗️ Технічна архітектура та алгоритми

```
               ┌────────────────────────────────────────────────────────┐
               │                  Вхідний запит оператора               │
               │   "нова пошта м. київ, 222" / "львів / наукова 1"     │
               └───────────────────────────┬────────────────────────────┘
                                           │
                                           ▼
               ┌────────────────────────────────────────────────────────┐
               │             Query Normalizer & Sanitizer               │
               │  • Зведення апострофів: [ʼ ' ’ `] ➔ [']                │
               │  • Очищення стоп-символів: [=, /, ,, ---, №]           │
               │  • Автоматична транслітерація розкладки en ➔ ua       │
               └───────────────────────────┬────────────────────────────┘
                                           │
                                           ▼
               ┌────────────────────────────────────────────────────────┐
               │              Faceted Entity Tokenizer                  │
               │  Виділення: [Топонім] [Район] [Область] [Вулиця] [№]   │
               └───────────────────────────┬────────────────────────────┘
                                           │
                                           ▼
               ┌────────────────────────────────────────────────────────┐
               │                Scoring Matrix Engine                   │
               │  • Збіг номера відділення:           +100 pts          │
               │  • Збіг точного міста (Anchor):      +50 pts           │
               │  • Збіг вулиці / орієнтиру:          +30 pts           │
               │  • Невідповідність області/району:   -2500 pts         │
               └───────────────────────────┬────────────────────────────┘
                                           │
                                           ▼
               ┌────────────────────────────────────────────────────────┐
               │          Client-Side Delivery & Rendering              │
               │   Рендеринг карток < 2ms, підсвічування токенів,       │
               │   готовність до копіювання в 1 клік                    │
               └────────────────────────────────────────────────────────┘
```

### Алгоритмічні складові:

1. **Нормалізатор запитів (Query Normalizer):**
   * Виправлення хаотичних символів пунктуації (`"м. Київ, 222"` $\to$ `Київ 222`, `"Львів / Наукова"` $\to$ `Львів Наукова`).
   * Інваріантне об'єднання всіх типів апострофів української мови (`ʼ`, `'`, `’`, `` ` ``).
   * Автоматичне виправлення помилкової розкладки клавіатури (`rbtd 1` $\to$ `Київ 1`).
2. **Scoring Matrix Engine:**
   * Замість крихких бінарних перевірок (`if (match)`) рушій використовує матрицю ваг із захистом від колізій. Якщо оператор вказує область або район, варіанти з інших областей отримують блокуючий штраф (**-2500 балів**), що повністю унеможливлює видачу помилкового міста.
3. **Автономність та масштаб даних:**
   * **26 588** населених пунктів України в структурованому індексі [`data/all_settlements.js`](file:///Users/Диск%20Д/06%20Проекти/НП%20+%20УКР%20-%20search%20/data/all_settlements.js).
   * **55 185** активних відділень і поштоматів у [`data/all_warehouses.js`](file:///Users/Диск%20Д/06%20Проекти/НП%20+%20УКР%20-%20search%20/data/all_warehouses.js).
   * **100% Client-Side:** Не потребує бекенд-серверів для пошуку. Нульова вартість інфраструктури (**$0/міс.**).
4. **PWA & Офлайн-архітектура:**
   * Реалізовано Service Worker ([`sw.js`](file:///Users/Диск%20Д/06%20Проекти/НП%20+%20УКР%20-%20search%20/sw.js)) із версіонуванням кешу (`v8.26.9`), стратегією `skipWaiting()` та `clients.claim()` для безшовного фонового оновлення додатку без блокування роботи користувача.

## 🚀 Швидкий старт для розробників

### Варіант 1: Zero Config (Відкриття в браузері)
Завдяки 100% клієнтській архітектурі, достатньо відкрити файл `index.html` у будь-якому сучасному браузері. Всі 55 000+ відділень та пошукові алгоритми запрацюють локально з коробки!

### Варіант 2: Локальний веб-сервер
```bash
# Клонувати репозиторій
git clone https://github.com/vadym-des/np-search-engine.git
cd np-search-engine

# Запуск через Node.js serve
npx serve .

# Або запуск через вбудований сервер Python
python3 -m http.server 8080
```
Відкрийте `http://localhost:8080` у браузері.

### Синхронізація бази через офіційні API:
Для оновлення вбудованих реєстрів відділень та населених пунктів передбачені автоматизовані скрипти:

```bash
# Завантаження та актуалізація реєстру всіх населених пунктів України
node scripts/download_all_settlements.js

# Завантаження та оптимізація бази всіх діючих відділень і поштоматів
node scripts/download_all_warehouses.js
```

> [!NOTE]
> Скрипти завантаження використовують офіційне API Нової пошти. Для запуску можна задати власний ключ через змінну середовища: `NOVA_POSHTA_API_KEY=YOUR_API_KEY node scripts/download_all_warehouses.js`.
